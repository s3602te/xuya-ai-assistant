# 問答總表擴充指令範本

把下面整段（從「===== 貼給 AI 的指令開始 =====」到結束）複製給任何一個 AI，
再附上你想新增的素材（一段自述、一份專案說明、一次面試被問倒的問題……），
它就會回給你可以直接貼進 `0731ai問答總表.csv` 的資料列。

貼進去之後記得跑：

```
cd xuya_vdb
python ingest_manual.py          # 沒改度量的話不用 --rebuild，會自動 upsert
cd ..
python rag_calibrate.py          # 確認分離度還是正的
```

> **為什麼一定要 `--rebuild`？**
> 向量的 ID 是照 CSV 行號編的（`qa_主檔_0`、`qa_主檔_1`…）。
> 如果你只是「新增」資料列，`upsert` 剛好能覆蓋；
> 但只要你**刪掉或搬動**任何一行，舊 ID 就會變成孤兒殘留在資料庫裡，
> 而且你從外面完全看不出來——查詢時卻會撈到那些早該消失的舊答案。
> 一百多筆重建只要幾秒，養成習慣永遠加。

## 為什麼規則要這樣訂（先看懂再用，效果差很多）

這幾條不是憑感覺，是實測數據推出來的：

**1. 一個主題要寫 3～5 種問法**
校準實測：問法幾乎照抄 CSV 原文時，相似度 0.905；改寫過的問法只有 0.573～0.853。
面試官不會照著你的 CSV 打字，所以**覆蓋問法比調任何參數都有效**。
每多一種自然的問法，就多守住一個入口。

**2. 答案要能單獨看懂**
命中高精準軌時，系統會**直接把 answer 當成標準答案**交給回覆節點。
所以答案不能寫「同上」「如前所述」，也不要依賴其他列的上下文。

**3. 絕對不要編造事實**
這是要拿去面試的。AI 幫你潤飾語氣可以，但日期、公司名、技術名詞、專案細節
都必須來自你真的做過的事。面試官追問一句就會破，
而且破的不只是那一題，是你整份履歷的可信度。

**如果某段素材你自己心裡覺得「這是唬爛的」，那就一個字都不要寫進去。**
真實的限制往往比誇大的故事更有說服力——
例如「顯卡只有 8GB VRAM，所以被迫設計大小模型分工」，
就比任何加油添醋的橋段都更能展現工程判斷力。

**4. 涉及個資的內容不要進知識庫**
手機、Email、完整住址這類資訊不要寫進去。
這個 AI 是任何人都能提問的，等於把個資放在一個可被任意查詢的介面上。
面試官需要聯絡方式，履歷上本來就有。

**5. 主語用「他」或「張序亞」**
知識庫講的是張序亞這個人，AI 是代言者。除了自我介紹類的開場白之外，
答案內文一律用第三人稱，語氣才不會錯亂。

===== 貼給 AI 的指令開始 =====

我在做一個 RAG 面試助理，知識庫是一份 CSV，欄位固定為 `source,question,answer` 三欄。
請幫我把下面提供的素材，轉成可以直接貼進這份 CSV 的資料列。

## 欄位規則

**source（主題分類）**：只能從下面這份清單挑一個，不要自創新分類。
如果素材真的不屬於任何一類，先告訴我，由我決定要不要開新分類。

```
自我介紹        ── AI 的開場白、「你是誰」這類入口問題
產品介紹        ── 這個面試 AI 本身：誰做的、用什麼技術、能回答什麼
基本資料        ── 生日、居住地、兵役、駕照、語言能力
求學與轉職      ── 學歷、培訓課程、轉職過程、轉職前的工作
工作經歷        ── 任職公司、職稱、年資、團隊角色（總覽層級）
職涯規劃        ── 期望職稱、產業、到職日、未來規劃
人格特質        ── 優缺點、衝突處理、溝通方式、工作態度
技術能力        ── 程式語言、框架、資料庫、開發工具、硬體條件
AI與LLM         ── 對語言模型與底層架構的理解
RAG與向量資料庫  ── 檢索增強生成的實作經驗與調校方法
多智能體架構     ── AI Agent 協作、任務拆解、流程設計
LINE客服專案    ── 創群科技的 LINE 官方 AI 客服（2025/4~）
柬埔寨稅務專案   ── 加油站稅務控制系統（2024/12~2025/4）
電子發票專案     ── 官網雲端電子發票模組（2024/9~2024/11）
DevOps與CICD    ── 容器化、自動化部署、流水線、憑證配置
系統防護        ── 錯誤處理、監控告警、穩定性設計
```

**特別注意「工作經歷」與各專案分類的分工**：
`工作經歷` 只放總覽層級的問題（在哪上班、年資多久、團隊角色）；
只要問題聚焦在某一個具體專案，就歸到該專案的分類。
這個切分是有實測依據的：早期把兩個不同專案的防幻覺作法都放在同一個分類下，
結果「你怎麼避免 AI 亂講話」這題撈錯專案，主題命中率就掉了一題。
**不同專案講同一個技術主題時，一定要分開放。**

**question（問題）**：用面試官會**自然講出口**的方式寫，不要寫成書面條目。
- ✅ 「你是怎麼轉職當工程師的」
- ❌ 「轉職歷程說明」

**answer（答案）**：
- 2～4 句，能單獨看懂，不依賴其他列
- 主語用「他」或「張序亞」（自我介紹類的開場白除外，那類用「我」）
- 只能使用我提供的素材，**不准補充任何我沒說過的事實**
- 素材不足以回答時，直接標記 `【素材不足】` 讓我補，不要自己想
- **不要寫入手機、Email、完整住址等個資**
- 描述與他人的衝突或爭論時，重點放在「怎麼化解」而不是「怎麼贏」，
  不要出現貶低對方的措辭（例如「絕殺」「他只能摸摸鼻子」）

## 產出規則

1. **每個主題請產出 3～5 種不同問法**，共用同一個或相近的答案。
   這是刻意的：向量檢索靠語意相似度比對，問法覆蓋越廣，命中率越高。
   問法要真的不一樣（換詞、換語氣、換切入角度），不要只改標點。

2. 用 CSV 格式輸出，**不要加表頭**（我會自己接在既有檔案後面）。
   答案裡若含逗號，整個欄位要用雙引號包起來。

3. 輸出前自我檢查這四點，任何一點不過就重寫：
   - [ ] source 是不是清單裡的其中一個
   - [ ] 有沒有出現我沒提供過的事實（公司名、日期、技術名詞、數字）
   - [ ] 每個答案單獨看得懂嗎
   - [ ] 同主題的問法真的夠不一樣嗎

## 擴充後的檢查清單

每次加完新資料，跑一次 `python rag_calibrate.py`，確認這三個數字：

| 指標 | 健康值 | 意義 |
| --- | --- | --- |
| 分離度 | 保持正值，越大越好 | 該命中與不該命中的題目分得開 |
| 主題命中率 | 越接近滿分越好 | 撈回來的條目主題正確 |
| 建議門檻 | 變動不大 | 大幅跳動代表新資料把分佈拉歪了 |

**如果分離度掉到負值**，通常是新加的答案寫得太籠統、跟太多主題都沾邊。
校準腳本會直接告訴你是哪幾題卡住，把那幾題寫具體一點就好。
